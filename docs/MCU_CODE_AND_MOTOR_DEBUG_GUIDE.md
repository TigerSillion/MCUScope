## 3. MCU Communication And Algorithm Architecture

### 3.1 Communication Flow

1. PC GUI sends UART frames (`0xAA 0x55`, command, payload length, payload, checksum).
2. `ICS2_RX26T.c` RX ISR stores bytes in ring buffer.
3. `ics2_watchpoint()` parses protocol and dispatches commands.
4. Whitelisted variables are read/written safely.
5. Scope sampling captures selected channels and returns waveform packets.

### 3.2 Motor Control Flow (High Level)

1. `r_mtr_ics.c/h` holds parameter and command interface variables (`com_*`).
2. `system_manager` transfers command variables into motor modules.
3. Speed module computes `Id/Iq` references.
4. Current module executes FOC current control and observer update.
5. Sensorless vector state machine manages run/stop/error transitions.
6. Optional modules (flying-start, flux-weakening, damping, stall detection, torque vibration compensation) modify control behavior under configured conditions.


## 4. Module-Level Explanation (Replaced Source Modules)

### 4.1 `ICS2_RX26T.c`

- Replaces closed communication library with C implementation.
- Implements:
  - Packet parser and checksum validation.
  - `GetInfo`, variable read/write, scope start/stop, trigger/sampling command handling.
  - Whitelist-only variable access.
  - Waveform upload packetization.

Key design constraints:

- No arbitrary pointer write access.
- All read/write variables must be listed in `s_scope_vars`.
- Scope data channel count and record length are bounded.

### 4.2 `r_motor_current_bemf_observer.c`

- BEMF observer and PLL estimation path.
- Provides `Ed/Eq` estimate and phase/speed correction signal.
- Includes parameter-gain initialization and runtime clamping for stability.

### 4.3 `r_motor_current_stall_detection.c`

- Detects stall using filtered absolute current behavior.
- Uses threshold level and threshold time.
- Sets stall detection flag for higher-level protection.

### 4.4 `r_motor_current_trq_vib_comp.c`

- Torque ripple suppression by LUT/PAT modes.
- Includes tracking filter, learning state transitions, and abnormal output protection.
- Supports 1F and optional 2F compensation targets.

### 4.5 `r_motor_current_volt_err_comp.c`

- Voltage error compensation via interpolation tables.
- Supports UVW/AB/off modes.
- Applies compensation with configurable voltage-limit ratio.

### 4.6 `r_motor_sensorless_vector_flyingstart.c`

- Flying-start sequence for restart while motor is already rotating.
- Multi-state control (`ON/OFF` pulses, active braking, transition to normal control).
- Outputs state/action for upper logic.

### 4.7 `r_motor_speed_fluxwkn.c`

- Flux-weakening logic with parameter validity checks.
- Handles bypass, active weakening, Id saturation, and invalid-parameter error states.

### 4.8 `r_motor_speed_opl_damp_ctrl.c`

- Open-loop damping feedback from `Ed` to stabilize transition region.
- Includes gain setup and feedback limit configuration.

### 4.9 `r_motor_speed_opl2less.c`

- Open-loop to sensorless transition helper.
- Computes torque/current transition commands using phase error and switch timing.


## 5. UART Whitelist Variables: Usage And Debug Meaning

Variables are defined in `ICS2_RX26T.c` (`s_scope_vars` table).

|---|---|---|---|---|
| `com_u1_system_mode` | W | `uint8` | Command event (`STOP/RUN/ERROR/RESET`) | Start/stop command source |
| `g_u1_system_mode` | R | `uint8` | Actual system mode | Confirms mode acceptance by state machine |
| `com_u1_ctrl_loop_mode` | W | `uint8` | Loop mode selection | Incorrect mode can block expected behavior |
| `com_u1_sw_userif` | W | `uint8` | UI switch mode | Select external/UI control path |
| `com_u2_offset_calc_time` | W | `uint16` | Current offset calibration time | Too short causes current bias |
| `com_u2_charge_bootstrap_time` | W | `uint16` | Bootstrap pre-charge time | Too short can cause power stage issues |
| `com_f4_ref_speed_rpm` | W | `float` | Speed reference | Main run command magnitude |
| `com_f4_speed_rate_limit_rpm` | W | `float` | Speed ramp rate limit | Too low appears as no acceleration |
| `com_f4_overspeed_limit_rpm` | W | `float` | Overspeed protection threshold | Low value can force trip/limit |
| `com_f4_speed_omega_hz` | W | `float` | Speed loop natural frequency | Dynamic response tuning |
| `com_f4_speed_zeta` | W | `float` | Speed loop damping ratio | Overshoot/oscillation suppression |

| `com_f4_current_zeta` | W | `float` | Current loop damping ratio | Current control stability |
| `com_f4_ol_ref_id` | W | `float` | Open-loop `Id` reference | Impacts startup magnetization |

| `g_st_sensorless_vector.f4_iu_ad` | R | `float` | Phase-U current | Current sampling health |
| `g_st_sensorless_vector.f4_iv_ad` | R | `float` | Phase-V current | Current sampling health |
| `g_st_sensorless_vector.f4_iw_ad` | R | `float` | Phase-W current | Current sampling health |

## 6. Recommended Motor Tuning Flow

Follow this order. Do not tune all parameters simultaneously.

1. Safety and signal sanity:
   - Verify current offset calibration and bus voltage.
   - Confirm phase currents are reasonable at idle.
2. Command path validation:
   - Set `com_u1_system_mode` to run command.
   - Confirm `g_u1_system_mode` and `st_stm.u1_status` follow correctly.
3. Open-loop startup validation:
   - Apply low `com_f4_ref_speed_rpm`.
   - Observe `f4_ref_speed_rad_ctrl`, `f4_iq_ref`, and phase currents.
4. Current-loop tuning:
   - Adjust `com_f4_current_omega_hz` and `com_f4_current_zeta`.
   - Target fast but non-oscillatory current response.
5. Speed-loop tuning:
   - Adjust `com_f4_speed_omega_hz`, `com_f4_speed_zeta`, `com_f4_speed_lpf_hz`.
   - Ensure measured speed converges to reference without hunting.
6. Sensorless quality check:
   - Observe `f4_phase_err_rad`, `f4_ed`, `f4_eq`.
   - Confirm phase error remains bounded and speed estimate remains stable.
7. Optional features after baseline stable:
   - Enable flying start, flux weakening, damping, stall detection, torque vibration compensation one-by-one.


## 7. Motor Not Rotating: Step-By-Step Debug Procedure

### Step 1: Confirm Command Reaches MCU

- Write `com_u1_system_mode = RUN event`.
- Observe:
  - `g_u1_system_mode`
  - `g_st_sensorless_vector.st_stm.u1_status`

If they do not transition, issue is command/state path, not motor algorithm.

### Step 2: Confirm Power Stage Preconditions

- Observe `g_st_sensorless_vector.f4_vdc_ad`.
- Verify bootstrap/offset parameters:
  - `com_u2_charge_bootstrap_time`
  - `com_u2_offset_calc_time`

If Vdc abnormal or offset not done, control loop may not start correctly.

### Step 3: Confirm Current Sensing Is Valid

- Observe:
  - `f4_iu_ad`, `f4_iv_ad`, `f4_iw_ad`

At standstill, offset-compensated currents should be near zero (small noise only).
Large bias indicates ADC/current calibration or hardware issue.

### Step 4: Confirm Speed Command Pipeline

- Observe:
  - `com_f4_ref_speed_rpm`
  - `st_speed_output.f4_ref_speed_rad_ctrl`

If `com` changes but internal command does not, parameter transfer path is blocked.

### Step 5: Confirm Torque-Producing Command Exists

- Observe:
  - `st_speed_output.f4_iq_ref`
  - `st_speed_output.f4_id_ref`

If `Iq_ref` stays near zero despite non-zero speed command, speed loop/gating logic is limiting output.

### Step 6: Confirm Sensorless Observer Quality

- Observe:
  - `st_current_output.f4_phase_err_rad`
  - `st_current_output.f4_ed`
  - `st_current_output.f4_eq`
  - `st_current_output.f4_speed_rad`

Persistent large phase error with unstable `Ed/Eq` usually indicates observer gain mismatch, bad current sense polarity, or wrong motor parameters.

### Step 7: Reduce Complexity (Feature Isolation)

- Temporarily use conservative baseline:
  - Disable optional features (flux-weakening, stall detection, torque vibration compensation, open-loop damping, flying start) in command parameters.
- Re-test base run.
- Re-enable features one-by-one to identify which block prevents startup.

### Step 8: Typical Fault Pattern Mapping

- `RUN command issued` but status remains STOP:
  - Check system mode command path and state machine event handling.
- Status enters ERROR quickly:
  - Check bus voltage thresholds, overcurrent path, and error flags in sensorless control structure.
- Speed reference present but actual speed zero:
  - Check `Iq_ref`, current feedback, and observer phase error.
- Current rises sharply without rotation:
  - Check phase sequence/polarity, motor parameter (`R/Ld/Lq/flux`), and observer gains.
